ElliottDB

An ultra-fast, single-executable relational database for Windows (elliottdb.exe, 373 KB static) and Linux (elliottdb). No Docker, no runtime DLLs, no external libraries—just launch one binary and connect over Binary EDB1, HTTP/1.1 JSON, or Text SQL on port 7432.

Architecture & Internals

Every subsystem in ElliottDB is partitioned into lock-striped shards so concurrent reads, writes, and network connections scale linearly across CPU cores without global bottlenecks.

64-Shard Buffer Pool

Pages (default 8192 B) map to 64 independent clock-sweep shards. Packed rid = (page_id << 16) | slot_idx delivers O(1) row fetches; --memory skips disk completely.

WAL Group Commit

CRC32C-checksummed records append to elliottdb.wal. Under full sync mode, concurrent writers coalesce into a single FlushFileBuffers/fdatasync. Crash recovery ignores uncommitted transactions.

Zero-Stall I/O & Workers

Connections come from dynamically growing slab chunks with atomic refcounts. IOCP swaps tx_buf into tx_active so overlapped sends never see a reallocated buffer.

SQL Dialect Reference

ElliottDB supports typed tables (INT, REAL, TEXT, BOOL, BLOB, TIMESTAMP), primary keys, auto-increment, constraints, joins, aggregations, transactions, and prepared statements.

-- DDL & Indexes (PRIMARY KEY & UNIQUE auto-create B+Tree/Hash indexes)
CREATE TABLE IF NOT EXISTS users (
  id INT PRIMARY KEY AUTO_INCREMENT,
  email TEXT UNIQUE NOT NULL,
  dept_id INT DEFAULT 0,
  salary REAL
);
CREATE INDEX idx_users_dept ON users (dept_id) USING HASH;
CREATE INDEX idx_users_sal  ON users (salary)  USING BTREE;
ALTER TABLE users ADD COLUMN active BOOL DEFAULT TRUE;

-- Multi-row INSERT, UPDATE, DELETE
INSERT INTO users (email, dept_id, salary) VALUES
  ('ada@edb.dev', 10, 180.0),
  ('linus@edb.dev', 10, 175.0);
UPDATE users SET salary = salary * 1.05 WHERE dept_id = 10;
DELETE FROM users WHERE active = FALSE;

-- Hash Joins, Aggregates, GROUP BY, HAVING, ORDER BY aliases, LIMIT/OFFSET
SELECT d.name, COUNT(*) AS headcount, AVG(u.salary) AS avg_sal
FROM users u
INNER JOIN depts d ON u.dept_id = d.id
WHERE u.salary BETWEEN 100.0 AND 250.0
GROUP BY d.name
HAVING COUNT(*) >= 1
ORDER BY avg_sal DESC
LIMIT 20 OFFSET 0;

-- Transactions & Prepared Statements
BEGIN;
INSERT INTO users (email, dept_id, salary) VALUES ('temp@edb.dev', 1, 50.0);
ROLLBACK;

PREPARE find_user AS SELECT id, email FROM users WHERE id = $1;
EXECUTE find_user(1);
DEALLOCATE find_user;

-- Introspection & Live Operations
EXPLAIN SELECT * FROM users WHERE id = 1;
SHOW TABLES;
DESCRIBE users;
SHOW CONFIG LIKE 'wal.%';
SHOW STATS;
SET query.slow_query_ms = 50;
CHECKPOINT;

Protocols & APIs

All three protocols share port 7432 via first-byte inspection (0x45 → Binary, HTTP verbs → HTTP/1.1, ASCII → Text).

import socket, struct

def send_query(sock, sql: str):
    payload = sql.encode("utf-8")
    # Header: magic='E', op=2 (QUERY), flags=0, len=u32 LE
    sock.sendall(struct.pack("<BBHI", ord("E"), 2, 0, len(payload)) + payload)
    magic, status, flags, rlen = struct.unpack("<BBHI", sock.recv(8))
    body = b""
    while len(body) < rlen:
        body += sock.recv(rlen - len(body))
    return status, flags, body

Building & Operations

:: Windows single static binary (MSVC /O2 /MT /W4)
build.bat
dumpbin /dependents build\elliottdb.exe   # WS2_32.dll + KERNEL32.dll only

# Linux single binary (GCC/Clang -std=c11 -O3)
make static                               # or ./build.sh --static
cmake -B build_cmake -G Ninja && cmake --build build_cmake

# Run automated end-to-end test & benchmark suite
python tests/test_suite.py
Durability Modes (wal.sync_mode): Use normal (default) for fast OS page-cache writes + periodic checkpoints, full for per-commit FlushFileBuffers/fdatasync with group commit coalescing, or off / --memory for ephemeral caches.
