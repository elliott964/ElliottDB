ElliottDB

Single-binary relational database written in portable C11 for Windows and Linux. Statically linked with zero runtime dependencies (382 KB on Windows x64, requiring only WS2_32.dll and KERNEL32.dll), binding 0.0.0.0:7432 with auto-tuned CPU threads and buffer pool on launch.

Architecture

Every hot path is partitioned across independent lock stripes or 64-way shards so concurrent connections and queries execute in parallel without global lock contention.

Slotted Pages & RIDs
Fixed pages (default 8192 B) store forward-growing slots and backward-growing row payloads. edb_rid_t packs (page_id << 16) | slot_idx for direct O(1) tuple fetch.
64-Shard Buffer Pool
Page IDs hash across 64 independent clock-sweep partitions (pager.c). Running with --memory keeps pages permanently resident without disk backing.
WAL & Crash Recovery
elliottdb.wal writes CRC32C-framed records (0x45444257). In full sync mode, concurrent commits coalesce into one FlushFileBuffers/fdatasync. Startup replay filters out uncommitted transactions.
B+Tree & Hash Indexes
PRIMARY KEY and UNIQUE columns auto-index. B+Tree leaves link doubly for range scans and use (key, rid) tie-breakers for non-unique keys; Hash indexes resize dynamically.
IOCP / epoll Reactor
Slab-allocated edb_conn_t slots track pending I/O and worker references atomically. Windows IOCP swaps tx_buf into tx_active when idle so an in-flight WSASend buffer is never reallocated.
Sharded Work Stealing
conn->worker_busy guarantees strict FIFO execution per TCP stream while different connections run concurrently across sharded queues with 5 ms timed waits for cross-shard stealing.

SQL Dialect

Supported column types: INT, REAL, TEXT, BOOL, BLOB, TIMESTAMP. Single-table SELECT, UPDATE, and DELETE automatically use equality or range index scans when predicates match indexed columns.

-- DDL & Indexes
CREATE TABLE IF NOT EXISTS users (
  id INT PRIMARY KEY AUTO_INCREMENT,
  email TEXT UNIQUE NOT NULL,
  dept_id INT DEFAULT 0,
  salary REAL
);
CREATE INDEX idx_users_dept ON users (dept_id) USING HASH;
CREATE INDEX idx_users_sal  ON users (salary)  USING BTREE;
ALTER TABLE users ADD COLUMN active BOOL DEFAULT TRUE;

-- Multi-row INSERT, UPDATE, DELETE
INSERT INTO users (email, dept_id, salary) VALUES
  ('ada@edb.dev', 10, 180.0),
  ('linus@edb.dev', 10, 175.0);
UPDATE users SET salary = salary * 1.05 WHERE dept_id = 10;
DELETE FROM users WHERE active = FALSE;

-- Hash Join, GROUP BY, HAVING, ORDER BY alias, LIMIT/OFFSET
SELECT d.name, COUNT(*) AS headcount, AVG(u.salary) AS avg_sal
FROM users u
INNER JOIN depts d ON u.dept_id = d.id
WHERE u.salary BETWEEN 100.0 AND 250.0
GROUP BY d.name
HAVING COUNT(*) >= 1
ORDER BY avg_sal DESC
LIMIT 20 OFFSET 0;

-- Transactions & Prepared Statements
BEGIN;
INSERT INTO users (email, dept_id, salary) VALUES ('temp@edb.dev', 1, 50.0);
ROLLBACK;

PREPARE find_user AS SELECT id, email FROM users WHERE id = $1;
EXECUTE find_user(1);
DEALLOCATE find_user;

-- Introspection & Runtime Control
EXPLAIN SELECT * FROM users WHERE id = 1;
SHOW TABLES;
DESCRIBE users;
SHOW CONFIG LIKE 'wal.%';
SHOW STATS;
SET query.slow_query_ms = 50;
CHECKPOINT;

Wire Protocols & HTTP API

A single TCP port (default 7432) multiplexes all three protocols by inspecting the first bytes of each connection: 0x45 selects Binary EDB1, HTTP method prefixes select HTTP/1.1 JSON, and any other ASCII selects Text Line SQL.

curl http://127.0.0.1:7432/health
curl http://127.0.0.1:7432/metrics
curl http://127.0.0.1:7432/config
curl -X POST http://127.0.0.1:7432/query -d "SELECT 1 + 1 AS sum"
curl -X POST http://127.0.0.1:7432/batch -d "CREATE TABLE t(id INT PRIMARY KEY); INSERT INTO t VALUES (1); SELECT * FROM t"
import socket, struct

def send_query(sock, sql: str):
    payload = sql.encode("utf-8")
    # 8-byte LE header: magic='E', op=2 (QUERY), flags=0, len=u32
    sock.sendall(struct.pack("<BBHI", ord("E"), 2, 0, len(payload)) + payload)
    magic, status, flags, rlen = struct.unpack("<BBHI", sock.recv(8))
    body = bytearray()
    while len(body) < rlen:
        body.extend(sock.recv(rlen - len(body)))
    return status, flags, bytes(body)

Binary Protocol (EDB1) 8-Byte Header

 0               1               2               3               4..7
+---------------+---------------+-------------------------------+-------------------------------+
| magic (0x45)  | op / status   | flags (uint16 little-endian)  | payload_len (uint32 LE)       |
+---------------+---------------+-------------------------------+-------------------------------+
Req  magic=0x45 ('E') | op: 1=PING, 2=QUERY, 3=BATCH, 4=AUTH, 5=PREPARE, 6=EXEC
Resp magic=0x52 ('R') | status: 0=OK..12=INTERNAL | flags: bit0=is_select, bit1=from_cache

Build & Durability

:: Windows static single binary (MSVC /std:c11 /O2 /MT /W4)
build.bat
dumpbin /dependents build\elliottdb.exe   # WS2_32.dll + KERNEL32.dll only

# Linux single binary (GCC/Clang -std=c11 -O3)
make static                               # or ./build.sh --static
cmake -B build_cmake -G Ninja && cmake --build build_cmake

# End-to-end test & benchmark suite
python tests/test_suite.py
WAL Sync Modes (wal.sync_mode): normal (default) writes to OS page cache immediately and syncs on checkpoint; full coalesces concurrent commits into one FlushFileBuffers/fdatasync; off or --memory disables disk flushing for ephemeral workloads.
